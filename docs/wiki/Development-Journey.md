# 컴포넌트 경계에 담긴 판단

시장 데이터와 뉴스·재무·거시 입력은 실패와 갱신 주기가 다르다. 하나의 계산 함수에 직접 외부 호출을 넣기보다 provider와 registry로 입력 경계를 나눴다.

뉴스는 수집, 중복·cluster 처리, 분석 호출 상태를 구분한다. 같은 뉴스의 반복 분석과 외부 요청 실패를 UI의 정상 값처럼 취급하지 않는 것이 중요하다.

AnalysisInputBuilder와 job manager를 분리해 분석 입력과 실행 상태를 관리한다. 설명 모델의 응답을 원시 시장 사실로 저장하지 않고 분석 결과로 다룬다.

가상매매의 수량·비용·청산 계산은 별도 trading 모듈이며 secret 저장은 DPAPI 기반이다. 화면의 분석과 체결·계정 보안의 책임을 분리한 구조다. 이 문서는 구현 경계에서 확인한 설계 판단을 설명하며 실제 기록이 없는 성능 개선 수치나 개발 날짜를 만들지 않는다.
